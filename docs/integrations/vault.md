# HashiCorp Vault

CALM Forge generates Vault policy artifacts from declared workload intent — policies, roles, and dynamic credential configurations expressed as HCL files in the same compilation pass that produces Terraform, Ansible, and Backstage outputs. The CALM workload spec describes the declared capabilities, the compliance scope, the regions the workload may run in, and the data classes it is permitted to touch; the compiler projects those predicates into Vault constructs that bind the workload's identity to a capability ceiling, a standing scope, and a lifecycle. The same `capabilities_granted ⊆ declared_capabilities` invariant that the OPA gate enforces at commit time is encoded into the Vault-side policy so that per-request narrowing can never elevate beyond the standing ceiling. Generated policies ship with provenance pointing back to the workload spec and a signed bundle the Vault operator can verify before installing.

The Day 2 integration runs in two directions. CALM Forge does not own Vault audit, but the Vault audit stream is one of the observation sources the agentic runtime + data plane convergence work depends on — Vault audit events flow into event aggregation platform for correlation, and on confirmed incident a SOAR playbook can call back through Vault and the data plane to revoke, mutate, or quarantine. The CALM Forge knowledge graph holds the typed predicates that make those policy mutations expressible as graph operations rather than ad hoc edits. The workload's standing ceiling is a graph property; quarantine is a typed transition; the evidence chain is queryable end-to-end through the same KG that drove the original authoring.

The Vault product remains the policy authority, the credential issuer, and the audit source. CALM Forge does not gate Vault, replace Vault policy authoring, or duplicate Vault's identity model. It is upstream of Vault for authored intent and adjacent to Vault for the agentic runtime closed-loop story.
